# M2 design brief: G1 all-in-wheel pack

## Goal

Move the 43-DoF G1 USD fixture from `UNIGYM_ISAACLAB2_G1_ASSET` into an
installed content pack. The approved distribution policy is one wheel with the
complete `g1.usd` + `configuration/**` tree; runtime configuration selects which
declared resource is used.

## Non-goals

- No asset trimming in M2. The pack intentionally ships the full 20-file,
  77.2MB-uncompressed tree (about 22MB compressed).
- No LFS pointer files or artifact-store indirection.
- No change to IsaacLab dependencies or G1 backend behavior.
- No split hand-variant packs or install-time extras.

## Files

Test packs:

```text
packages/unigym-test-pack-g1/                G1 content distribution
tests/consumer/test_g1_pack.py               installed pack consumer test
tools/check_wheel.py                         G1 wheel-content gate
pyproject.toml                               workspace/import contracts
```

Core:

```text
tests/backends/isaaclab2/conftest.py         g1_usd uses pack_runtime
tests/backends/isaaclab2/test_g1_builder.py  g1 pack marker
tests/backends/isaaclab2/README.md           lane documentation
docs/testing.md                              G1 asset-env removal
.github/workflows/{ci,nightly}.yml           wheelhouse includes G1 pack
```

## Classes, protocols and registries

- Pack entry point: `g1 = unigym_test_pack_g1:pack_root`.
- Manifest face: `assets`, id `g1.usd`, resource `assets/g1.usd`.
- Core marker use: `requires_test_packs("g1")`.
- Owner of the full asset tree: the G1 pack distribution.
- Owner of runtime resource resolution: `pack_runtime("g1")` through the
  test-pack plugin and core pack API.

## Interactions and data flow

1. The IsaacLab 2 environment installs the plugin and G1 pack wheel.
2. The G1 test module declares `requires_test_packs("g1")`.
3. `g1_usd` resolves `assets/g1.usd` through the installed pack root.
4. The root `g1.usd` keeps its relative `configuration/**` references; the
   complete tree is present beside it.
5. Runtime code/tests select the declared resource explicitly; no ambient
   asset-path variable or hidden default is used.

## Invariants and failure modes

- Entry-point name equals manifest name and the wheel contains all 20 G1 files.
- `g1.usd` and `configuration/**` preserve their relative layout.
- A missing G1 pack fails the strict `isaaclab2` lane at test setup.
- D0 still collects no pack-dependent test.
- G1 asset bytes match the provisioned fixture exactly.
- The pack ships `THIRD_PARTY_NOTICES.md` in the wheel.
- No `UNIGYM_ISAACLAB2_G1_ASSET` reference remains in core tests/docs/workflows.

## Compatibility and migration

- Public API impact: none.
- Schema impact: new `unigym.pack/1` content pack.
- Distribution impact: G1 wheel is about 22MB compressed; source stores the
  complete 77.2MB tree.
- Migration: remove the G1 asset env variable; no fallback.
- CI: the existing test-pack wheelhouse installs the G1 wheel in addition to
  the plugin/cartpole pack.

## Tests

- Pack consumer: manifest, root USD, all configuration files, byte-identity
  spot checks and directory layout.
- Wheel: build/install all four wheels outside the checkout, strict consumer.
- Core: G1 fixture uses pack runtime; G1 module marker; D0 guard unchanged.
- Dog lane: full strict IsaacLab 2 suite with the installed G1 pack.
- Strict miss: removing only the G1 pack fails G1 tests at setup.

## Risks and open questions

- Risks: wheel/source size growth, PyPI 100MB per-file limit, binary diff
  review, CI wheelhouse cache size.
- Alternatives considered: artifact-store wheel, LFS source, split variants.
  All are rejected for M2; one all-in-wheel distribution is simpler.
- Open questions: none for M2.
- Rollback path: remove the G1 pack/marker and restore the env read; core
  behavior is otherwise unchanged.
