# M3 design brief: CI drift and lanes

## Goal

Make the independent test-pack repository exercise its own contracts in CI,
against a pinned core checkout and against core `main`, and document the
selectable pack lanes.

## Non-goals

- No PyPI or internal wheel publishing automation.
- No per-pack `-m` marker argument; subset selection remains installed-set or
  path selection.
- No core production changes.
- No release/tag automation.

## Files

```text
.github/workflows/ci.yml       PR lanes: lint, unit, wheel, strict, subsets
.github/workflows/nightly.yml  pinned/main drift and wheel lanes
ci/core-pin.toml               repository + pushed core commit pin
docs/ci.md                     lane contract and local commands
Makefile                       local lane aliases
README.md                      CI/lane pointer
```

## Classes, protocols and registries

- `ci/core-pin.toml` owns the core repository and pinned pushed commit.
- The workflow owns checkout and lane orchestration, not test semantics.
- Existing `tools/check_wheel.py` remains the isolated wheel owner.
- No new runtime registry or plugin option.

## Interactions and data flow

1. A job checks out this repository.
2. It reads `ci/core-pin.toml`, checks out `unsigned123/unigym` at the pinned
   commit into `core/`, and creates the sibling `../unigym-core` symlink the
   workspace source expects.
3. `uv sync --all-packages` installs the plugin and all pack distributions.
4. The lane runs its selectors and flags.
5. Nightly `core-main` repeats with core `main`; `core-pinned` repeats with the
   pin.

## Invariants and failure modes

- The pinned ref must be a pushed commit; a local-only hash is invalid.
- Subset-basic installs only plugin + basic, so Cartpole/G1 consumer tests skip.
- Strict-full installs every pack and fails on any missing declared pack.
- Strict-missing installs plugin + basic and must fail on a Cartpole-marked
  selector with the teaching message.
- Wheel lane builds/installs all wheels outside the checkout and runs with
  `--strict-test-packs`.
- Nightly core-main drift is a failure, not a skip.
- D0/core lanes remain unchanged.

## Compatibility and migration

- CI requires read access to the core repository.
- Workspace `[tool.uv.sources]` still points at `../unigym-core`; the workflow
  supplies that path.
- No package metadata, schema or public API change.
- Local development remains `uv sync --all-packages` with a sibling core.

## Tests

- Run each workflow command locally where possible: lint, unit, strict-full,
  subset-basic, strict-missing, wheel.
- Verify the core pin exists and is pushed.
- Verify `uv sync` resolves both pinned and current core checkouts.
- Nightly GitHub execution is reported as unrun when not available.

## Risks and open questions

- Risks: checkout access, large dependency install time, uv cache behavior,
  symlink path assumptions, core-main lock drift.
- Alternatives considered: install-only wheel jobs (rejected for PR lanes
  because they hide workspace wiring), testing against a PyPI core release
  (core is not published).
- Open questions: none block M3.
- Rollback path: remove workflows/CI docs; the plugin and packs are unchanged.
