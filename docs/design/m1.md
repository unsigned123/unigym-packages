# M1 design brief: cartpole migration

## Goal

Move the IsaacLab 2 Cartpole USD fixture out of the test-only environment
variable and into an installed content pack:

- add `unigym-test-pack-isaaclab-cartpole` with `cartpole.usd` and its
  `Props/instanceable_meshes.usd` companion;
- rewrite the core IsaacLab 2 Cartpole fixture through `pack_runtime`;
- mark the affected backend tests with `requires_test_packs`;
- make the `isaaclab2` lane strict for test packs;
- remove `UNIGYM_ISAACLAB2_ASSET_CACHE` from tests, docs and workflows.

## Non-goals

- No G1 pack or G1 fixture migration (M2).
- No large-asset artifact store; Cartpole is small and ships directly.
- No change to IsaacLab dependency provisioning or backend behavior.
- No core runtime API change.

## Classes, protocols and registries

- New pack distribution entry point:
  `isaaclab_cartpole = unigym_test_pack_isaaclab_cartpole:pack_root`.
- Manifest face: `assets`, id `isaaclab_cartpole.usd`, resource
  `assets/cartpole.usd`.
- Core marker: `requires_test_packs`, registered in core and a resource marker
  for fast-lane derivation.
- Lane entry `pytest_args`: a validated list of extra pytest arguments; the
  `isaaclab2` lane carries `["--strict-test-packs"]`.
- Owner of pack data: the cartpole pack distribution.
- Owner of resource resolution: `unigym.pack_api.discover` via the plugin.
- Owner of lane command construction: `tools/ci/run_lane.py`.

## Interactions and data flow

1. The IsaacLab 2 environment installs the plugin and cartpole pack wheels.
2. `pytest_configure` discovers the installed pack.
3. A cartpole test carries `requires_test_packs("isaaclab_cartpole")`; a
   missing pack skips locally or fails under the lane's strict flag.
4. The `cartpole_usd` fixture calls `pack_runtime("isaaclab_cartpole")` and
   resolves the `assets` resource.
5. The USD keeps its relative `./Props/instanceable_meshes.usd` reference, and
   both files ship under `pack/assets/`.

## Invariants and failure modes

- The pack entry-point name equals the manifest name.
- The Cartpole USD and its `Props` companion are in the same relative layout.
- Core tests never read `UNIGYM_ISAACLAB2_ASSET_CACHE`.
- A missing cartpole pack fails the strict `isaaclab2` lane at test setup.
- The D0 lane collects no test carrying `requires_test_packs`.
- `requires_test_packs` removes an item from the derived fast lane.
- Lane `pytest_args` are non-empty strings and are passed verbatim.
- G1 still uses `UNIGYM_ISAACLAB2_G1_ASSET` until M2.

## Compatibility and migration

- Public API impact: none.
- Schema impact: new `unigym.pack/1` content pack only.
- Dependency impact: the IsaacLab 2 lane needs plugin + cartpole pack wheels.
- Migration: remove the cartpole asset cache variable; keep G1 variable.
- CI provisioning: a wheelhouse variable supplies plugin/pack wheels to the
  self-hosted IsaacLab job; tests never read that path.

## Tests

- Pack consumer: manifest, resource resolution, USD/companion presence and
  relative reference.
- Wheel: build/install all wheels outside the checkout and run the consumer.
- Core meta: marker registry, D0 no-pack guard, lane `pytest_args` validation.
- Core backend: all cartpole tests marked; strict lane resolves the pack.
- Fast-suite impact: no pack-marked test can be fast.

## Risks and open questions

- Risks: Cartpole USD provenance/licensing; conda lane mutation during local
  verification; CI wheelhouse path availability; pack wheel data globs.
- Alternatives considered: keep the asset cache env variable (rejected);
  commit the asset to core tests (rejected by pack boundary).
- Open questions: none block M1. G1 distribution remains an M2 owner decision.
- Rollback path: remove the cartpole pack/markers and restore the fixture env
  read; core behavior otherwise unchanged.
